Chromflock

chromflock is a software package to deconvolve bulk Hi-C data into putative single-cell structures. The overall scheme is borrowed from PGS [1] from Frank Alber lab although it is not a direct fork.

Chromflock will:

  • Work with haploid as well as diploid structures.

  • Can integrate GPSeq data for radial preferences.

  • Supports spherical as well as an ellipsoidal domain for the beads.

The documentation is not complete at the moment and it is suggested that anyone interested in chromflock start by reading the papers from Frank Alber lab, since much of the terminology used here is introduced by them.

Input and output

As input, chromflock takes:

  • A contact probability matrix, \(A\), where \(A_{ij}\) denotes the proportion of structures that should have a contact between site \(i\) and \(j\), i.e. a number in \([0,1]\).

  • A label matrix, \(L\), which points out which chromosome each bead belongs to.

  • A vector specifying radial preferences for each bead, \(R\). Possibly together with a vector specifying the probability of each radial preference to be used.

  • The number of structures to generate, \(N\).

  • A list of theta values, \(\theta_1 (=1) > \theta_2 > ... > \theta_T\), where \(T-1\) is the number of epochs to be run and \(\theta_t\) specifies which contacts from the \(A\)-matrix that should be used in epoch \(t\).

  • The number of times that each epoch should be re-run, \(C\).

  • A lua script which defines the dynamics of the simulations.

The output consists of:

  • Coordinates for all beads in all structures, \(X\).

  • The contact indicator tensor, \(W^{(n)}_{i,j}\) which says which contacts are assigned to which structures.

  • Log files and some pre-calculated summary statistics such as the average radial profile.

Workflow and time complexity

  • Initialize \(S\) structures with \(N\) beads. (aflock)

  • Run the M-step to find initial structures. (mflock)

  • For each of the \((T-1)\) epochs:

    • For each of the \(C\) AM-cycles:

      • (re)-assign contacts (aflock)

      • Find structures (mflock)

  • Finalize (aflock)

The time consumption is typically dominated by the M-step (mflock) and the number of mflock commands to be run is \(N_M = S((T-1)C+1)\).

Typical values would be \(S=10,000\), \(T=6\), \(C=4\), i.e. \(N_M=210,000\). Using about \(3,000\) beads, an M-step takes \(12\) s. Using a machine with 40 cores this will take: \(210,000\times12/(40\times3,600)\) s or about \(= 17.5\) hours.

Geometry

The domain of the simulations is always an ellipsoid, however for simplicity we present it for a spherical domain first. In that case the sphere has a radius \(R_s=1\). The beads have a radius, \(R_b\) and beads in contact are set to have a distance below \(R_c=4.0R_b\).

Typically \(R_b\) is set to get a certain volume occupancy. The volume of the spherical simulation domain is:

\[V_s = \frac{4\pi}{3}\]

and the volume of the \(N\) beads is

\[V_b = N(R_b)^3\frac{4\pi}{3}\]

setting \(V_b/V_s=V_q\) gives

\[R_b = \sqrt[3]{\frac{V_q}{N}}.\]
